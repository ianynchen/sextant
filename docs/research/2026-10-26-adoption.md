# Adoption of the remaining frameworks and languages, measured

Measurement date: 2026-10-26. Gathered from public sources, never estimated. The question was
which gap to close next, now that Spring Boot and Quarkus are delivered. The user ruled the
priority order from it the same day; `docs/COVERAGE.md`, "Priority order", records that order.

**How it was checked.** Three research agents gathered the numbers. The controller re-read
the figures the ranking rests on against their sources:

- **Verified, matching exactly:**
  - the Stack Overflow 2025 professional-developer language and web-framework percentages;
  - JetBrains' 2021–2025 language series (`devecosystem-2025.jetbrains.com/_data/pl_dynamics_large.csv`);
  - SlashData's Q3 2024 backend-developer split (`developernation.net`);
  - the State of Kotlin 2026 Spring/Ktor shares.
- **Not re-read by the controller:**
  - the Stack Overflow 2021 figures (the page could not be fetched);
  - the JetBrains Java-framework percentages, which the agent decoded from a chart and rounded.

**What it showed, in one paragraph.** Every remaining Java/Kotlin framework is at or below
about 7% of Java developers. Ktor is the only one above the survey floor: 7% of Java developers,
51% of Kotlin backend developers. For languages, Node.js (49.1%), Python (54.8%) and C# (29.9%;
ASP.NET Core 21.3% against Spring Boot's 15.6%) lead current use among professionals. TypeScript,
Python, Go and Rust are growing. C# and Swift are flat, and JavaScript's share is shrinking as
TypeScript takes it. No source separates backend use per language except SlashData Q3 2024
(JS/TS 41%, Java 39%, Python 37%, Go 11%, Rust 5% of backend developers).

### 5. Ranking of the unsupported frameworks, by strongest available evidence

Ordering rule: survey evidence first, then Maven dependents, then GitHub. Only Ktor appears in a survey above the 5% floor. The others are all at or below 5% in the JetBrains survey, so for them the order rests on Maven and GitHub counts, which measure something different (see caveats).

1. Ktor. JetBrains 2025: 7% of Java developers (up from 2% in 2021) and 51% of Kotlin backend developers, second only to Spring (61%). Maven: ktor-client-core has 601 dependents, ktor-server-core 113 to 172. GitHub: 623 repositories on ktor-server-core, 14,555 stars.
2. Vert.x. Largest library footprint among the web frameworks: vertx-core 256 dependents on the latest version and 2,521 on 4.3.7; 23,813 GitHub repositories; 14,682 stars. Survey: 1% in JRebel 2023 and at or below 5% in JetBrains every year.
3. Quartz. Highest Maven count of any unsupported item: 1,198 dependents on 2.5.2 and 4,290 on 2.3.2 (more than Quarkus core's 2,144 peak). 6,758 stars. No survey asks about schedulers.
4. Akka and Pekko (taken together). akka-actor 703 to 881 at peak, pekko-actor 457 at peak, akka-http 301, pekko-http 231. 13,281 stars for Akka, 1,655 for Pekko. No survey figure. Akka's newest open-licence release is 2.8.8 (2024-10-28); newer activity is in Pekko.
5. Play. play_2.13 162 at peak (2.8.11), 28 on the latest; org.playframework:play_3 32 to 77. 12,621 stars. At or below 5% in JetBrains every year.
6. Helidon. helidon-webserver 111 at peak, 35 on the latest; 3,841 stars. "About 5%" in the Eclipse cloud-native survey 2024; at or below 5% in JetBrains.
7. Spark Java. 213 at peak, 106 on the last release; 37,382 GitHub repositories, 9,633 stars. Unmaintained since 2022/2023, so the current user base is not growing.

### 6. Caveats

- Survey self-selection. JetBrains states that its respondents skew toward JetBrains IDE users, and the Java questions are shown only to people who list Java among three primary languages. Azul, JRebel and Eclipse recruit through their own audiences: Azul's 2025 result (Micronaut 39%, almost level with Spring Boot 42%) is far from JetBrains (Micronaut at or below 5%, Spring 65%) and from JRebel (Micronaut 6%, Spring Boot 59%). The three disagree by large margins, so treat these as "which are at all common", not as exact shares. The JetBrains chart values were decoded from the page's SVG and are rounded to whole percent.
- The Kotlin figures (61% Spring, 51% Ktor) come from a summary page that gives no question wording or sample size, and are a share of Kotlin backend developers, not all JVM developers. Kotlin is a minority of JVM code, so Ktor's 51% does not translate to 51% of anything else.
- JetBrains does not publish values for frameworks at or below 5%, so Vert.x, Helidon, Play and Micronaut cannot be ranked against each other from it.
- No survey asked about Quartz, Akka/Pekko, GraphQL Kotlin or Spark, so their rank rests on Maven and GitHub only.
- deps.dev counts only other published Maven artifacts that depend on a given version. That favours libraries that other libraries embed (Quartz, Vert.x, Akka, Camel, Ktor client) and undercounts frameworks used to write applications that are never published (Spring Boot apps, Quarkus apps, Micronaut apps, Play apps). Micronaut shows only 7 direct dependents on micronaut-core because apps depend on modules and the BOM, not on core; the same artifact-choice effect applies to every row, so counts across rows are not like for like.
- The per-version count is a snapshot of one version. Old versions (2.7.18, 4.3.7, 2.3.2) show higher counts because the dependents have had years to accumulate and have not all upgraded. The latest-version count is low for every project for the opposite reason. Neither is a count of distinct projects.
- Scala-suffixed artifacts (_2.12, _2.13, _3) split Akka, Pekko and Play across several artifacts; the numbers above are the largest ones read, not a total.
- GitHub "Repositories that depend on" includes student, tutorial and throwaway repositories. Spark Java (37,382) and Javalin (12,335) look large because both are common in tutorials; those counts say little about production use. GitHub only exposes some Maven packages, so many cells are "not found". Stars measure interest, not use.
- mvnrepository.com "Used By" counts could not be read (HTTP 403), so no figures from that site are in this file. Maven Central download counts are not public.
- Akka's licence change in 2022 moved open-source users to Pekko; counting Akka alone understates the Akka-family footprint and counting both double-counts users who run both.
- This file measures adoption only. It says nothing about how much of each framework Sextant can derive from bytecode.

### 4. Ranking for backend-service use, strongest evidence first

Rank by combining the SO 2025 professional language and framework numbers, JetBrains 2025 usage, and Octoverse. Backend-only per-language data does not exist in any source I found, so the order below is a judgment from general language use plus framework rows.

1. JavaScript and TypeScript (Node.js ecosystem). Node.js 49.1% of professionals (the highest backend technology row), Express 20.3%, NestJS 7.4%; JS 68.8% and TS 48.8% as languages; TypeScript is #1 on Octoverse 2025. Cannot split JS from TS at the framework level.

3. C# / .NET. 29.9% professional; ASP.NET Core 21.3% is the top single server framework after Node.js and is above Spring Boot (15.6%); ASP.NET (older) a further 15.0%. JetBrains .NET survey: 50% of .NET professionals work on backend services. Octoverse #5.

### 5. Caveats

- Stack Overflow measures who answers the survey, not who writes production services. Its respondents lean toward web, scripting, and frontend work; "used" is any extensive work in the past year, so JavaScript counts front-end use too.
- The SO 2025 survey is the only edition with a professional-developer split; the 2026 survey page shows all respondents only (n = 14,099 for languages, a smaller sample than the full 30,903) and a shorter framework list. The 2026 numbers are therefore not directly comparable to the 2025 professional column. 2026 changes worth noting: Rust 18.0% (up from 14.8% all), FastAPI 18.5% (up from 14.8%), Express 15.6% (down from 19.9%), Spring Boot 12.8% (down from 14.7%).
- JetBrains surveys over-represent JetBrains IDE users (IntelliJ, PyCharm, Rider, GoLand, WebStorm). JetBrains says responses are weighted but "some bias is likely present" and its data shows higher Java and Kotlin than Stack Overflow's. Java 49% there versus 29.6% in SO is an example.
- Octoverse counts people committing on GitHub, so it includes front end, tooling, scripts, infrastructure (HCL, Shell) and AI work; it does not separate services. The growth of TypeScript is credited by GitHub to AI-assisted development and front-end frameworks, not only to backends. Rust and Swift are not in the top 10, so no figures exist for them there.
- RedMonk combines GitHub with Stack Overflow questions; TIOBE counts search-engine hits. Neither measures backend use. TIOBE ranks TypeScript #38, which conflicts with every use-based source, a sign of its limits.
- No language-by-backend split was found in SO, JetBrains public pages, Octoverse, or the CNCF/SlashData Q3 2025 report. The JetBrains Data Playground and the SlashData tables might have one; they were not accessible to me.
- Framework rows with no entry (Gin, Echo, Fiber, Vapor, Actix) are absent from the survey list, not at zero. Go and Swift server use is therefore under-measured at framework level.
- Two of the four language sources (SO, JetBrains) measure how many developers use a language, which is not how many services are written in it. One developer at a Java shop may also list JavaScript and Python.
- Sextant reads compiled code. JavaScript, TypeScript and Python have no compiled artifact in the usual build; Go, Rust, C# and Swift do. This note is a fact about the languages, not a measure from these sources, and the sources above do not address it.

### 5. Caveats

- **Column change at Stack Overflow.** 2021-2025 pages offer both All Respondents and Professional Developers. The 2026 page has no professional column (its filters are work experience and "used for AI"), so 2026 values must be compared with the 2025 all-respondents column (1.1b, 1.2b), not the professional one. The Stack Overflow results blog post for 2026 does not describe any sampling or weighting change; it calls the approach "more editorial this year".
- **Stack Overflow samples shrank.** Language-question base (all respondents) as read: 83,052 (2021), 71,547 (2022), 60,171 (2024), 31,771 (2025), 14,099 (2026). Small shifts between 2025 and 2026 (a point or two) are within what a smaller sample can produce; I did not compute margins of error. The 2025 jump in several rows (Node.js professionals 40.7 to 49.1, JavaScript 64.6 to 68.8, Python 46.9 to 54.8) is larger than any other single-year change and I could not find an explanation.
- **Stack Overflow item changes.** Node.js moved from the language list (2021) to web frameworks (2022). "Spring" became "Spring Boot" in 2023. NestJS appears from 2023. Axum appears from 2025. FastAPI is in all years but was a small base in 2021. Gin, Echo, Fiber, Vapor are in no year.
- **Stack Overflow measures respondents who use the site**, skewed toward web and scripting; "used" is any extensive work in the past year, so JavaScript includes front end.
- **JetBrains** over-represents JetBrains IDE users; its own text says "some bias is likely present". Java (49) and Kotlin (18) are higher than at Stack Overflow because of this. The 2021 sample over-represented PHP/Laravel users. The 2025 CSV re-states earlier years (2024 TypeScript 37 in the CSV, 35 in the 2024 report text). The JetBrains microservices-language chart comes from the Java report and covers Java developers only.
- **JetBrains plan-to-adopt percentages are published for 2025 only** (and as a partial snippet for 2021); other years give only the order. "Planning to adopt" measures intention among all respondents, not realized adoption, and "60% not planning to adopt" in 2025 shows most people do not plan any change.
- **SlashData** numbers are modelled estimates of active developers, restated from edition to edition (the 2025 population page says 47.2M, "up 50% from 31M in 2022", while the Q1 2023 report said 35.6M at that date and Q1 2021 said 24.3M). Q1 2021 values come from an older model and should not be compared with Q1 2023+ values. Several rows (Q1 2022, Q1 2024) come from press summaries, not from a SlashData page, and the Q1 2023 Lua figure was dated Q3 2023 on the page (not used). The SlashData reports themselves are behind a sign-up form (not read). The only backend-specific language split (Q3 2024) is one wave with 2,754 respondents.
- **Octoverse** changed its metric each year: 2022 growth of "usage" (undefined), 2023 percentages with unnamed bases, 2024 order only, 2025 monthly contributors Aug vs Aug. The years are not comparable and GitHub counts front-end, scripts, infrastructure (HCL, Shell) and AI work. Octoverse 2021 was not found.
- **No source separates backend services by language except** SlashData Q3 2024 (all developers who write server/cloud code) and the JetBrains Java-developer subset. A cross-tab of language by "provide APIs and services" exists in the JetBrains raw data (98 MB zip, not read) and in the JetBrains Data Playground (not accessible).
- **Not read:** Postman 2022-2024 PDFs (5.6 to 8.0 MB); the JetBrains RawData.zip (98 MB); SlashData State of the Developer Nation full reports (form-gated); Stack Overflow Admired/Desired data; CNCF Q1 2025 report; the Stack Overflow 2023 base sizes.
- **Compiled-code fit (a fact about the languages, not from these sources):** Sextant reads compiled code; Go, Rust, C# and Swift produce compiled artifacts, while JavaScript, TypeScript and Python usually do not.
