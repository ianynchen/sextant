# Quartz — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every Quartz trigger a module builds becomes a `scheduled_work` entry, with its job's handler, its schedule kind and its schedule. A trigger whose schedule lives in a database table becomes a `partial` entry at its dispatcher. The trace then continues from the handler through the call graph.

**Architecture:**
- **No Quartz reader.** Quartz is a catalog over machinery that already exists:
  - the `fluent` chain walk, moved first into its own module;
  - the value walk;
  - `dispatch.py`;
  - the `supertype` + `dispatch` catalog vocabulary;
  - `effective_calls.py`.
- **Three general changes, each for every catalog:**
  - autoboxing is read as the constant the source wrote;
  - a branch between literals is `narrowed`;
  - the execute-join finds its arguments through the value walk.
- **One new engine** turns chain captures into `scheduled_work` rows, beside the annotation engine.

**Tech Stack:** Python 3.13, DuckDB, pytest; Java fixtures built with Maven, JDK 21.

**Spec:** `docs/superpowers/specs/2026-10-28-quartz-design.md` (approved 2026-10-29; rulings 1–7 in its §1).
