# Deployment-set conditions Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every existence verdict resting on something a deployment can set (profile and property conditions) is "not evaluated", with the repository's own reading as evidence. The diff compares declared condition expressions, and `dependency` carries conditions.

**Architecture:** The bean model declares `set_by: deployment` per condition kind (catalog data, backed by probe CP-47). `bean_conditions.py` keeps `_holds`/`_profile_holds` as the repository's reading under Spring's rules. A new `_judged` turns that reading into evidence and decides the verdict only from the environment's own definition. Everything downstream (`endpoint_conditions` view, `bean_presence`, documents, system document) reads the same rows. The boundary diff narrows `conditions` to `{kind, expression}` and adds it to `dependency`.

**Tech Stack:** Python 3.13, DuckDB, YAML catalogs, pytest; probes in Python over jars from the local Maven repository.

**Spec:** `docs/superpowers/specs/2026-10-23-deployment-set-conditions-design.md`

## Review Focus

- **A `profile` condition in its own environment.** `@Profile("h2")` in environment `h2` must still HOLD (resolved), and `@Profile("!h2")` must FAIL there; only these stay decided.
- **The `default` environment.** Nothing decides anything there: `@Profile("default")` and `@Profile("!prod")` are `unresolved` in `default`.
- **Presence propagation.** `@ConditionalOnMissingBean` whose only competitor is a `@Profile`-gated bean was decided; it must now be `unresolved`. A competitor with no conditions still decides it.
- **The placeholder reason.** Apollo's `${apollo_profile}` reason must survive as evidence, not be replaced by the generic one.
- **Diff noise.** A config-only change (`billing.enabled` flipped in `application-prod.yml`) must produce a `boundary-property` change and NO `conditions` change on the endpoint.
