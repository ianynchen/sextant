## Verbs and positions

- Verb helpers, all surfaces: `get options head post put patch delete`, plus `request`.
  `httpx` alone adds `stream(method, url)` (module-level and on `Client`).
  `requests` has no `stream` call.
- `url`: positional index 0 on every verb helper; `request(method, url)` and
  `stream(method, url)`: method index 0, url index 1 (module level, `Session`, `Client`, `AsyncClient`).
- requests' second positional parameter: `get(url, params)`, `post(url, data, json)`,
  `put/patch(url, data)`; `delete/head/options(url)` only. Everything else is `**kwargs`.
- httpx verbs take `url` as the only positional parameter; the rest is keyword-only.

## Body keywords

- requests: `json=`, `data=`, `files=` (via `**kwargs` on the verbs, named on `Session.request`).
  `content=` is not accepted: `requests.post(url, content=b"x")` raises
  `TypeError` (`...got an unexpected keyword argument 'content'`).
- httpx: `content=`, `data=`, `json=`, `files=` on `post`, `put`, `patch`, `request` at module
  level and on `Client`/`AsyncClient`. **`get`, `head`, `options`, `delete` have none of them**
  in httpx (module level, `Client` and `AsyncClient`).
- Wire: `requests.post(json={"k":1})` sends a JSON body; `data={"k":"v"}` sends `k=v` as
  `application/x-www-form-urlencoded`; `httpx.post(content=b"raw")` sends `raw`.

## base_url

- `requests.Session` has no base URL: no `base_url` attribute; `Session(base_url=...)` raises
  `TypeError`; `session.get("/relative")` raises `MissingSchema` ("Invalid URL '/relative': No scheme supplied...").
  Every requests URL is absolute.
- httpx, quoted from `httpx/_client.py:391 Client._merge_url`:

  > To merge URLs we always append to the base URL. To get this behaviour correct we always
  > ensure the base URL ends in a '/' separator, and strip any leading '/' from the merge URL.
  > ... `Client(base_url="https://www.example.com/subpath")` ... `build_request("GET", "/path").url`
  > `URL('https://www.example.com/subpath/path')`

  with `_enforce_trailing_slash` (`:234`): the stored `base_url` ends in `/` whenever it has a path.
  Measured (the same for `Client` and `AsyncClient`):

  | base_url | request path | final URL |
  |---|---|---|
  | `https://h.example/api` | `/users` | `https://h.example/api/users` |
  | `https://h.example/api` | `users` | `https://h.example/api/users` |
  | `https://h.example/api/` | `/users` | `https://h.example/api/users` |
  | `https://h.example` | `/users` | `https://h.example/users` |
  | `https://h.example/api` | `` (empty) | `https://h.example/api/` |
  | `https://h.example/api` | `https://other.example/x` | `https://other.example/x` (absolute wins) |
  | `https://h.example/api` | `./x` | `https://h.example/api/x` |
  | `https://h.example/api` | `x?q=1` | `https://h.example/api/x?q=1` |
  | `https://h.example/api` | `//other.example/x` | `https://h.example/api/x` (host dropped, path appended) |
  | `https://h.example/api` | `../x` | `https://h.example/x` (dot segments normalised) |

  Without `base_url`, a relative path raises `httpx.UnsupportedProtocol`.
  A leading `/` never resets to the host root when a base path exists: it is stripped, then appended.
