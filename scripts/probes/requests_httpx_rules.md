# `requests` and `httpx` call rules (plan 3, Task 0)

Measured by `requests_httpx_rules.py`, run as
`fixtures/orders-fastapi/.venv/bin/python -I scripts/probes/requests_httpx_rules.py`.
Every line below is an `assert` in the script. Requests go to a local HTTP server, so the wire
result is what the library sends.

**Version scope.** requests 2.34.2 and httpx 0.28.1 (httpcore 1.0.9), pinned in the fixture's
`pyproject.toml` and `uv.lock`. Every verdict holds for these versions and no other.

## Verbs and positions

- Verb helpers, all surfaces: `get options head post put patch delete`, plus `request`.
  `httpx` alone adds `stream(method, url)` (module-level and on `Client`).
  `requests` has no `stream` call.
- `url`: positional index 0 on every verb helper; `request(method, url)` and
  `stream(method, url)`: method index 0, url index 1 (module level, `Session`, `Client`, `AsyncClient`).
- requests' second positional parameter: `get(url, params)`, `post(url, data, json)`,
  `put/patch(url, data)`; `delete/head/options(url)` only. Everything else is `**kwargs`.
- httpx verbs take `url` as the only positional parameter; the rest is keyword-only.

## Body keywords

- requests: `json=`, `data=`, `files=` (via `**kwargs` on the verbs, named on `Session.request`).
  `content=` is not accepted: `requests.post(url, content=b"x")` raises
  `TypeError` (`...got an unexpected keyword argument 'content'`).
- httpx: `content=`, `data=`, `json=`, `files=` on `post`, `put`, `patch`, `request` at module
  level and on `Client`/`AsyncClient`. **`get`, `head`, `options`, `delete` have none of them**
  in httpx (module level, `Client` and `AsyncClient`).
- Wire: `requests.post(json={"k":1})` sends a JSON body; `data={"k":"v"}` sends `k=v` as
  `application/x-www-form-urlencoded`; `httpx.post(content=b"raw")` sends `raw`.

## Verb case (ruling R10)

`requests.request("get", url)`, `Session().request("patch", url)`, `httpx.request("get", url)`
and `Client().request("delete", url)` reach the server as `GET`, `PATCH`, `GET`, `DELETE`.
requests upper-cases in `PreparedRequest.prepare_method` (`self.method.upper()`), httpx in
`Request.__init__` (`self.method = method.upper()`). A verb written as a string literal is
therefore read upper-cased.

## Several body keywords (ruling R11)

Measured on the wire, with `json=`, `data=`, `files=` and `content=` given together:

- requests (`PreparedRequest.prepare_body`): `files=` makes a multipart body of `files` and
  `data` together; otherwise a non-empty `data=` is the (form) body; otherwise `json=`
  (`if not data and json is not None`). Order: **`files` > `data` > `json`**. An empty
  `data={}` gives way to `json=`.
- httpx (`httpx._content.encode_request`): `content=` wins; then `files=` (multipart, with
  `data`); then a non-empty `data=`; then `json=`. Order: **`content` > `files` > `data` >
  `json`**. A `data=` that is not a mapping is sent as `content=` (with a
  `DeprecationWarning`). An empty `data={}` gives way to `json=`.
- A call with none of them sends an empty body, in both libraries: no body.

Positions of the body parameters: requests `post(url, data, json)` has `data` at 1 and `json`
at 2; `put`/`patch(url, data)` `data` at 1; `Session.request` has `data` at 3, `files` at 6,
`json` at 15; `requests.request(method, url, **kwargs)` takes every body by keyword. httpx
takes every body by keyword.

## `with` returns the client (ruling R13)

`with httpx.Client(...) as c`, `async with httpx.AsyncClient(...) as c` and
`with requests.Session() as s` bind the name to what `__enter__`/`__aenter__` returns. Each is
defined on that class (`__qualname__` `Client.__enter__`, `AsyncClient.__aenter__`,
`Session.__enter__`), and each returns the client itself — measured `entered is opened` for all
three. Quoted: `httpx._client.Client.__enter__` and `AsyncClient.__aenter__` end `return self`
after opening their transports; `requests.sessions.Session.__enter__` is `return self`.
`Session` has no `__aenter__`.

## base_url

- `requests.Session` has no base URL: no `base_url` attribute; `Session(base_url=...)` raises
  `TypeError`; `session.get("/relative")` raises `MissingSchema` ("Invalid URL '/relative': No scheme supplied...").
  Every requests URL is absolute.
- httpx, quoted from `Client._merge_url` in `httpx/_client.py`:

  > To merge URLs we always append to the base URL. To get this behaviour correct we always
  > ensure the base URL ends in a '/' separator, and strip any leading '/' from the merge URL.
  > ... `Client(base_url="https://www.example.com/subpath")` ... `build_request("GET", "/path").url`
  > `URL('https://www.example.com/subpath/path')`

  with `_enforce_trailing_slash` : the stored `base_url` ends in `/` whenever it has a path.
  Measured (the same for `Client` and `AsyncClient`):

  | base_url | request path | final URL |
  |---|---|---|
  | `https://h.example/api` | `/users` | `https://h.example/api/users` |
  | `https://h.example/api` | `users` | `https://h.example/api/users` |
  | `https://h.example/api/` | `/users` | `https://h.example/api/users` |
  | `https://h.example` | `/users` | `https://h.example/users` |
  | `https://h.example/api` | `` (empty) | `https://h.example/api/` |
  | `https://h.example/api` | `https://other.example/x` | `https://other.example/x` (absolute wins) |
  | `https://h.example/api` | `./x` | `https://h.example/api/x` |
  | `https://h.example/api` | `x?q=1` | `https://h.example/api/x?q=1` |
  | `https://h.example/api` | `//other.example/x` | `https://h.example/api/x` (host dropped, path appended) |
  | `https://h.example/api` | `../x` | `https://h.example/x` (dot segments normalised) |

  Without `base_url`, a relative path raises `httpx.UnsupportedProtocol`.
  A leading `/` never resets to the host root when a base path exists: it is stripped, then appended.
