# CP-click — click 8.5.0's command, group, parameter and program-name rules, read from its source

**Version scope.** `click` **8.5.0**, the distribution installed in Sextant's own `.venv` (the
version Sextant's `pyproject.toml` resolves), as `importlib.metadata` reports it in the run
below. Every rule is read from the source of the function that implements it, by
`inspect.getsource`; the harness aborts if a quoted line is missing. Other click versions are
outside this measurement: the suffix rule in §2 is new in 8.2, and earlier versions keep the
whole function name.

**Why it was measured.** `src/sextant/catalogs/click.yml` and
`src/sextant/catalogs/value-models/click.yml` (design 2026-11-06-reading-decorators §5, approved)
state how a click program's commands are named, which decorators hand the function back, how
groups nest, and what each parameter decorator says. Each statement cites a rule below.

**What this probe does not settle.** It runs no program. `nargs` on an argument (§5) is read by
the catalog only as `nargs=-1` (`optional_when`, design §3f): the `nargs=0` that click's
`nargs > 0` also makes optional is not stated. `version_option`'s first positional
parameter is the version, not an option name, and `password_option` and `version_option`
default their names (`--password`, `--version`): the catalog states both hand the function back
(§3) and gives neither a `request_params` entry. Boolean pairs (`--shout/--no-shout`) are flags
click recognises without `is_flag`; the catalog reads `is_flag` only.

## What each rule means for the catalog

1. **Registration.** `command(name=None, cls=None, **attrs)`: the name is position 0 or the
   keyword `name`, so the catalog's roots read `url: { arg: 0, keyword: name }`.
   `Group.command(*args, **kwargs)` builds `command(*args, **kwargs)(f)` and calls
   `self.add_command(cmd)`; `Group.group` does the same with `group`. The decorator these
   return is called with the function (`__call__`), which is the chain's terminal.
2. **A name not written** is `f.__name__.lower().replace("_", "-")`, and where
   `rpartition("-")` leaves a last part in `{"command", "cmd", "group", "grp"}`, the part before
   it: the catalog's `path_fallback: {name: construct_name, lower: true, replace: {"_": "-"},
   drop_suffixes: [command, cmd, group, grp]}`.
3. **The decorators between.** `option` and `argument` return `decorator`, whose body is
   `_param_memo(f, cls(param_decls, **attrs)); return f`: applied to a function, the result is
   that function (`result_returns: arg0`). `password_option` and `version_option` return
   `option(*param_decls, **kwargs)`, the same decorator. `group(name)` with `name` callable is
   the parenthesis-free form: it builds the group at once, with no `__call__`, and is not read.
4. **The program's name.** A group's own name is not typed: `main` takes `prog_name` from
   `_detect_program_name`, which is `sys.argv[0]`'s base name for a file or entry point. So the
   outermost word is the entry point's name (`[project.scripts]`), and with none the named hole
   `<program>`.
5. **Parameters.** `Argument.__init__`: with `required` not given, the argument is required where
   no `default` is written and `nargs` is above 0; the catalog reads `nargs=-1`, the spelling for
   "any number", as `optional_when` (design §3f). An argument takes exactly one declaration
   (`_parse_decls`), its name. An option's declaration that is an identifier is its parameter's
   name; each other one is a spelling a user types (`opts.append(decl)`), which the catalog
   reads with `name_arg: all_strings` and the handler's parameter names (design §3f). `Parameter.__init__`'s `required: bool = False`, which `Option` reaches through
   `**attrs`: an option is optional unless `required` is written. `Option`'s `is_flag` makes an
   option that takes no value.
