# `humps.main.camelize`, copied exactly (plan 2, final review M2)

Backs the `humps_camelize` strategy word (approved by the user on 2026-11-09) in
`catalogs/shape-models/pydantic.yml` and `shapes/model_fields._humps_camelize`.
`scripts/probes/humps_camelize.py` produced every result below.

**Version scope.** pyhumps **3.8.0** (the version mealie locks) on Python **3.14.10**, as the
running process reported them (`importlib.metadata.version("pyhumps")`), run with mealie's
environment (`examples/py-mealie/.venv`). The function was copied from that installation's
`humps/main.py` (`camelize`, `UNDERSCORE_RE`, `_is_none`). Every verdict below holds for that
version and for no other.

**Why not `to_camel`.** `pydantic_naming.md` §1 mapped `humps.main.camelize` to `camel`
(pydantic's `to_camel`) because the two agree on all 465 of mealie's field names. They are two
different functions, and the final review measured realistic names where they differ
(`is_2fa_enabled`), so a `resolved` wire name from the old mapping could be false.
