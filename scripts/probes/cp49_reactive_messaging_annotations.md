# CP-49 — which annotations name a SmallRye Reactive Messaging channel, and which direction Quarkus gives each

**Version scope.** Everything below is measured against the jars **as their own manifests state
them**: `microprofile-reactive-messaging-api` (`Bundle-Version` — it states no
`Implementation-Version` — `3.0.1` when this record was made);
`smallrye-reactive-messaging-api`, `-provider` and `-kafka` (`Implementation-Version`
`4.25.0`); and `quarkus-messaging` and `quarkus-messaging-deployment` at both `3.17.5` (the
fixture's Quarkus) and `3.40.1.1` (the `examples/quarkus-quickstarts` field corpus's), read by
`probe.py` out of the local Maven repository — never the directory name this harness found
them under, which is the CP-5 failure the convention exists to prevent. These are platform
behaviour of those releases and a later one is free to change any of them, so the verdicts
here bound to the versions in the table and to nothing wider.

**Why it was measured.** The Quarkus messaging design (spec 2026-10-24, §3a) puts the channel
annotations into a new catalog, `smallrye-reactive-messaging.yml`: `@Incoming` and `@Outgoing`
on a method, `@Channel` on an injected emitter (outbound) or stream (inbound), and the
repeatable containers. Their names, where each may sit, their members and defaults, and which
direction the framework gives the channel each names are the framework's, so they are read
off the jars before the catalog states them. The SmallRye API jar SHADES
`org.eclipse.microprofile.reactive.messaging.*`, so both copies are read: what a module
compiles against is whichever its classpath resolves first.

## What the rows say

**Rows 1–3 and 5–7 — three annotations, one `String value()` each, no default.**
`@Incoming` and `@Outgoing` sit on a METHOD only; `@Channel` is a CDI qualifier that sits on a
METHOD, CONSTRUCTOR, FIELD or PARAMETER (an injection point), its `value()` `@Nonbinding`. No
member has a default, so every use names its channel. The two copies agree except in one
respect: **the SmallRye-shaded `@Incoming` and `@Outgoing` are `@Repeatable`** (rows 5–6,
containers `@Incomings` / `@Outgoings`, rows 9–10, METHOD-only, `value()` an array of the
single annotation), and the MicroProfile 3.0.1 originals (rows 1–2) are not. A method may
therefore carry several `@Incoming`s directly, which `javac` stores as one `@Incomings`.

**Rows 11–12 — the deprecated spellings.** `io.smallrye.reactive.messaging.annotations.Channel`
and `…annotations.Emitter` are `@Deprecated` copies of the MicroProfile ones; Quarkus still
reads both (rows 18 and 23: `LEGACY_CHANNEL`, `LEGACY_EMITTER`).

**Rows 4, 8, 12–17 — what an emitter is.** `Emitter`, `MutinyEmitter` and the legacy `Emitter`
are interfaces (`send…` methods), not annotations. Which injected types count as emitters is
not a fixed list: it is every type a bean's `@EmitterFactoryFor` names. The provider names
the three emitters (row 14); the Kafka connector adds `KafkaTransactions` and
`KafkaRequestReply` (row 15); Quarkus 3.40.1.1 adds `ContextualEmitter` (row 17), 3.17.5 none
(row 16).

**Rows 18–22 and 23–27 — the direction Quarkus gives each, the same at both versions.**
`extractComponents` reads `@Incoming`/`@Incomings`/`@Outgoing`/`@Outgoings` off bean methods
and `@Channel` (either spelling) off injection points. `@Incoming` (and its container) produces
an INCOMING channel and `@Outgoing` an OUTGOING one (rows 20, 25). An injected `@Channel` is an
OUTGOING channel when the injection point's type is one of the `@EmitterFactoryFor` types
(`handleEmitter` → `createEmitter` → `produceOutgoingChannel`), and an INCOMING one otherwise
(`handleChannelInjection` → `produceIncomingChannel`) — so `@Channel` on a `Multi` or a
`Publisher` is inbound (rows 21, 26). An empty `@Incoming` or `@Outgoing` value fails the
build (rows 22, 27).

## What this does NOT measure

* **Message payload types and acknowledgement.** The rows say which channel a method or
  injection point names and in which direction, not what flows on it.
* **Plain (non-Quarkus) SmallRye wiring.** The direction rule is read from Quarkus's build-time
  `WiringProcessor`. A SmallRye application on another CDI container wires through the
  provider's runtime graph, which this probe does not read; for an `@Incoming`/`@Outgoing`
  method the direction is the annotation's own meaning either way.
* **Which channels become boundaries.** That is CP-50: orphan detection, the configured
  connector and the single-connector attachment.
* **An `@EmitterFactoryFor` type from a jar not read here.** Rows 14–17 list the factories in
  the jars named in the table; another connector or extension may add one. The rule — a type
  named by any bean's `@EmitterFactoryFor` is an emitter — is what rows 21 and 26 read.
