# CP-wrappers — what `functools`, `contextlib` and tenacity's decorators do with the function, read from their source

**Version scope.** The standard library of Python **3.14.10**, as `sys.version_info` reports it
in the run below, and `tenacity` **9.1.4**, the distribution installed in Sextant's own `.venv`,
as `importlib.metadata` reports it. Every rule is read from the source of the function that
implements it, by `inspect.getsource`; the harness aborts if a quoted line is missing. Other
Python and tenacity versions are outside this measurement.

**Why it was measured.** `src/sextant/catalogs/value-models/python-wrappers.yml` (design
2026-11-06-reading-decorators §3e, approved) states which library decorators hand the function
back and which return a wrapper that runs it. A decorated name holds the decorator's result, so a
call of the name reaches the function's body only through such a statement.

**What this probe does not settle.** It runs no program. `lru_cache` and tenacity's `retry` each
have two spellings, and only one is stated: `@lru_cache` and `@retry` with the function as the
one argument return the wrapper at once (`result_calls: arg0`); `@lru_cache(maxsize=128)` and
`@retry(stop=...)` return a decorator, and the function arrives at THAT decorator's call. The
walk reads `result_calls` only where argument 0 is a function, so the second spelling states
nothing and a call through it ends at the library, as before. A wrapper may not run the function
on every call (`lru_cache` answers a repeated call from its cache): a call edge says the call can
run it.

## What each rule means for the value model

- **`functools.wraps`: `result_returns: arg0`.** `wraps(wrapped)` is `partial(update_wrapper,
  wrapped=wrapped, …)`; calling it with the wrapper runs `update_wrapper(wrapper, wrapped=…)`,
  which ends `return wrapper`. So `@wraps(fn) def w` holds `w`.
- **`functools.cache`: `result_calls: arg0`.** `cache(f)` is `lru_cache(maxsize=None)(f)`, the
  wrapper of `f`, which calls `f` with the call's arguments.
- **`functools.lru_cache`: `result_calls: arg0`, the bare spelling.** With a callable first
  argument it builds `_lru_cache_wrapper(user_function, …)` and returns it at once. With
  `maxsize` an integer or None it returns `decorating_function`, and the function is that
  decorator's argument: argument 0 is no function, so nothing is stated for it.
- **`contextlib.contextmanager`, `asynccontextmanager`: `result_calls: arg0`.** The result is
  `helper(*args, **kwds)`, which builds the manager with `func, args, kwds`, and the manager's
  `__init__` runs `self.gen = func(*args, **kwds)`.
- **`tenacity.retry`: `result_calls: arg0`, the bare spelling.** `retry(f)` with one callable
  argument is `retry()(f)`, whose wrapper is `BaseRetrying.wraps`'s `wrapped_f`, which runs
  `copy(f, *args, **kw)`: the retrying object calls `f` with the call's arguments. With options,
  `retry(...)` returns `wrap`, and argument 0 is no function.
