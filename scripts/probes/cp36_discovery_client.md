# CP-36 — what a service-discovery lookup hands back, and what identifies it

Spec `docs/superpowers/specs/2026-10-17-outgoing-endpoint-addresses-design.md` §4,
register entry `OI-142`. Re-run it rather than trusting this file:
`JAVA_HOME=<jdk21+> bash scripts/probes/cp36_discovery_client/run.sh`.

**The question.** A module that resolves its own peer addresses writes this, and its class
file contains no URL at all — verified on `spring-petclinic-genai-service`, zero
occurrences of `http://`:

```java
discoveryClient.getInstances("customers-service").get(0).getUri() + "/owners"
```

So which part of the chain carries the identity of the service being called, and does the
rest of the chain preserve it? The answer decides whether a destination can be published
for three outbound rows that read `(unresolved)` today.

**Version scope.** Everything below is measured against
**`org.springframework.cloud:spring-cloud-commons` 5.0.0** — the version the archive
reported in its own manifest — which is what `spring-cloud-dependencies:2025.1.0` manages
and therefore what `examples/spring-petclinic-microservices` builds against. Both types
live in that artifact and in neither `spring-cloud-loadbalancer` nor
`spring-cloud-gateway-server-webflux`. A later release is free to change any of it, and
the verdicts here bound to the one that produced the table.

## Verdicts

**1. The service id is one argument, and the result is a COLLECTION.**
`getInstances(java.lang.String)` returns `List<ServiceInstance>`. So the identity of the
value this call produces is argument 0 — the ordinary `identified_by` shape — and the chain
then has to cross a collection to reach an address.

**2. `getUri()` takes NOTHING, which is why `arg` could not express this.** An
`identified_by` entry answers *which argument of a call carries the value its result stands
for*. `getInstances` fits. The two calls after it do not: `List.get(int)`'s argument is an
index, and `getUri()` has no arguments at all. Both need to say *"my result stands for
whatever my RECEIVER stands for"*, and that is the `from_receiver` form this probe
justifies.

**3. `createUri` builds `%s://%s:%s` — scheme, host, port, and no path.** This is the
reading with a consequence beyond the identity question: the runtime URI carries no path
component, so in `getCustomerServiceUri() + "/owners"` the literal tail is the WHOLE path
rather than a suffix of one. Without it, publishing `/owners` would be a guess about where
the authority ended.

*Bounded to the default implementation.* `getUri()` is `public abstract` on the interface,
so a custom `ServiceInstance` may return anything; `DefaultServiceInstance.getUri()`
delegates to the static `createUri` measured here, and that is what a module using
`DiscoveryClient` receives.

## What this means for the identity table

Three entries, each citing this probe:

* `{owner: DiscoveryClient, method: getInstances, arg: 0}` — the ordinary form.
* `{owner: java.util.List, method: get, from_receiver: true}` — element access preserves it.
* `{owner: ServiceInstance, method: getUri, from_receiver: true}` — so does the accessor.

**The second is the broad one, and what makes it safe is measured rather than argued.** An
entry on `List.get` is read by every catalog at once, over every list in the estate — so
for a topic list it must NOT propagate, or `List.of("orders", "audit").get(0)` would answer
both topics for one element. The table already separates the two cases and the walk
separates them again at resolve time: a SINGLE-VALUED identity resolves to one answer and
propagates, an ENUMERATING one (`all_strings`) resolves to several and is refused.

Measured over the shipped table, 23 entries: **three are enumerating** — `List.of`,
`Arrays.asList`, `Subscriptions.topics`, exactly the topic lists — and of the twenty
single-valued ones **exactly one produces a collection**, `Collections.singletonList` at
`arg: 0`. `singletonList("x").get(0)` IS `x`, so propagating is right there too. The gate
is therefore the exact line between the entries that must not propagate and the rest, not
caution about a case nobody has.
