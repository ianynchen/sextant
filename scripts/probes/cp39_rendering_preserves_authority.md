# CP-39 — a RENDERING call preserves an authority, and nothing else

**Version scope.** Everything below is measured against **the JDK reporting
`JAVA_RUNTIME_VERSION` `21.0.12.1`** — the version the installation states in its own
`release` file, read by `probe.py` before it measures anything, never the value this harness
was handed. That is the version CI pins (`setup-java` 21) and the version every fixture is
built with. Both answers are platform behaviour and a later release is free to change
either, so the verdicts here bound to `21.0.12.1` and to nothing wider.

**Why it was measured.** `OI-138` cause 3 is the last thing between
`spring-petclinic-genai-service` and a complete service map: three calls whose peer is a
service NAME the code states and whose host is a registry lookup. `OI-142` built the
grammar for the chain — `from_receiver`, `yields: authority` — proved it resolves end to
end, and then recorded that it **cannot ship**, because javac inserts a call this table
must not describe:

> `String.valueOf` cannot be declared as an identity for this purpose. … An
> `identified_by` entry says what a value STANDS FOR; a join publishes text as an ADDRESS;
> those are different claims and they part company exactly where it matters.

That objection is correct and this probe is what bounds it.

## What the two rows say

**Row 1 — `String.valueOf(Object)` RENDERS its argument.** It calls `Object.toString()`, with
the four characters `null` for a null argument. So its result is a rendering of the value and
never the value's identity, which is exactly `OI-142`'s objection, confirmed off the
platform's own bytecode rather than from documentation.

**Row 2 — it is in the chain, unavoidably.** javac inserts it around every non-`String`
operand of a concatenation, so the walk meets it between `getUri()` and the template:

```java
restTemplate.getForObject(customers() + "/owners", String.class);   // customers() returns URI
```

## Q3 — when is it safe to cross?

The two kinds of value this table identifies part company here:

| the value stands for | its `toString()` | crossing it to JOIN the text |
|---|---|---|
| an **address** — a JMS `Queue` whose identity is `"orders"` | a vendor debug string | **WRONG**: publishes an address that never existed, at `resolved` |
| an **authority** — the instances of `customers-service` | that instance's URL | **SOUND**: the row's claim is the PEER, and the peer is still `customers-service` |

So the dividing line is a word the table already has. `yields: authority` says the value
names WHO is called; the join writes it scheme-relative (`//customers-service/owners`,
RFC 3986 §4.2) and `split_url` files it under `peer` with the path beside it. Nothing
claims the program built that string — `OI-142`'s ruling 2, already shipped.

**The rule this probe supports, and no wider one:** a rendering call propagates an identity
that yields an AUTHORITY and refuses one that yields an address. Not "`String.valueOf` is an
identity", which is what `OI-142` refused and what would publish the vendor debug string as
a destination.

## What this does NOT measure

* **Other renderings.** `Objects.toString`, `StringBuilder#append(Object)`, a `String.format`
  conversion and an explicit `.toString()` are the same shape and are NOT declared: javac
  inserts `String.valueOf` on its own, so that one is the shape the estate actually
  contains, and an entry per plausible sibling would be a mechanism with no measured input.
* **A rendering whose `toString` is overridden to something else.** For an authority the
  claim does not depend on what the text is — the peer comes from the identity, not from the
  rendering — so an exotic `toString` changes the text we never publish rather than the
  column we do.
