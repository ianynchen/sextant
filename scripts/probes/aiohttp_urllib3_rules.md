## Defining symbols

| Surface | Defined in | Note |
|---|---|---|
| `aiohttp.ClientSession` and its `get/post/put/patch/delete/head/options/request` | `aiohttp.client.ClientSession` (file `aiohttp/client.py`) | `aiohttp.ClientSession is aiohttp.client.ClientSession`; `__qualname__` of each verb is `ClientSession.<verb>` |
| `aiohttp.request` (module level) | `aiohttp.client.request` (file `aiohttp/client.py`) | `aiohttp.request is aiohttp.client.request`; `__module__` reads `aiohttp.client` |
| `urllib3.PoolManager.request` | `urllib3._request_methods.RequestMethods.request` (file `urllib3/_request_methods.py`) | `PoolManager` does not define `request`; it is `PoolManager.__mro__[1]`. Same for `request_encode_body` and `request_encode_url` |
| `urllib3.PoolManager.urlopen` | `urllib3.poolmanager.PoolManager` | its own |
| `urllib3.request` (module level) | `urllib3/__init__.py`, `urllib3.request` | calls `_DEFAULT_POOL.request(...)`, a module-level `PoolManager` |

`PoolManager.request` therefore must be catalogued under the defining class
`urllib3._request_methods.RequestMethods`, with the receiver `urllib3.PoolManager` resolved
through inheritance.

## Verbs and positions

- aiohttp `ClientSession`: `get options head post put patch delete`, plus `request`. The module
  has `request(method, url, ...)` only: no `aiohttp.get`, `aiohttp.post`, ... and no `stream`.
- aiohttp `url`: positional 0 on every verb. `request(method, url)`: method 0, url 1
  (`ClientSession.request` and `aiohttp.request`). `ClientSession(base_url, ...)`: `base_url` is
  positional 0.
- aiohttp bodies are never positional. `post/put/patch` name `data` keyword-only
  (`post(self, url, *, data=None, **kwargs)`); `get/head/options/delete` and `request` have
  no named body; `json=` (and `data=` on those) travel in `**kwargs` to
  `ClientSession._request`, whose parameters are `(method, str_or_url, params, data, json, ...)`.
- urllib3 has **no verb helpers**: no `get`, `post`, ... on `PoolManager` or in the module. Only
  `request`.
- urllib3 `PoolManager.request(self, method, url, body=None, fields=None, headers=None,
  json=None, **urlopen_kw)`: method 0, url 1, body 2, fields 3, headers 4, json 5.
- urllib3 `urllib3.request(method, url, *, body, fields, headers, preload_content,
  decode_content, redirect, retries, timeout, json)`: method 0, url 1, everything else keyword-only.

## Verb case

`request(method, url)` upper-cases the method string; measured on the wire for
`ClientSession.request("get", ...)`, `aiohttp.request("delete", ...)`,
`PoolManager.request("get", ...)` and `urllib3.request("delete", ...)`: they arrive as
`GET`, `DELETE`, `GET`, `DELETE`. `method=` / `url=` keywords behave the same. Quoted:

- `aiohttp.client.ClientSession._request`: `method = method.upper()`; and
  `aiohttp.client_reqrep.ClientRequest.__init__`: `self.method = method.upper()`.
- `urllib3._request_methods.RequestMethods.request`: `method = method.upper()`.

A verb written as a string literal is therefore read upper-cased.

## aiohttp bodies

Measured on the wire (`ClientSession.post`):

| keyword | wire body | Content-Type |
|---|---|---|
| `json={"k":1}` | JSON | `application/json` |
| `data={"k":"v"}` | `k=v` | `application/x-www-form-urlencoded` |
| `data=b"raw"` | `raw` | `application/octet-stream` |
| `data="text"` | `text` | `text/plain` |
| `data=aiohttp.FormData(...)` with a file field | multipart | `multipart/form-data` |
| none, POST | empty | `application/octet-stream` (an empty body is still labelled) |
| none, GET | empty | none |

`get(url, json=...)` and `get(url, data=...)` send the body (no keyword is refused on the
bodiless verbs, unlike httpx).

**`data=` with `json=` together has no precedence: it raises.** Quoted from
`aiohttp.client.ClientSession._request`:

> `if data is not None and json is not None:`
> `    raise ValueError("data and json parameters can not be used at the same time")`

Measured: `data={"d":"v"}`, `data=b"x"`, `data=""` and `data={}` each with `json={"j":1}` raise
`ValueError` before anything reaches the server. The test is `is not None`, so `data=None` with
`json=...` (and `json=None` with `data=...`) is fine and sends the one body. The same holds on
`request("GET", ..., data=..., json=...)`.

## `async with` (aiohttp)

`async with aiohttp.ClientSession() as s` binds the session itself: `ClientSession.__aenter__` is
`return self` (measured `entered is opened`). `async with s.get(url) as r` and `await s.get(url)`
send the identical request (measured: same method, path, body and Content-Type); entering or
awaiting the call changes nothing on the wire. `aiohttp.request(...)` is entered the same way.
(urllib3: `with urllib3.PoolManager() as p` binds the manager itself, `PoolManager.__enter__`
returns `self`.)

## aiohttp `base_url`

`ClientSession(base_url=...)` (positional 0 or keyword) with `_build_url`, quoted from
`aiohttp.client.ClientSession._build_url`:

```python
url = URL(str_or_url)
if self._base_url and not url.absolute:
    return self._base_url.join(url)
return url
```

and the construction check in `aiohttp.client.ClientSession.__init__`:

```python
self._base_url = URL(base_url)
self._base_url_origin = self._base_url.origin()
assert self._base_url.absolute, "Only absolute URLs are supported"
if self._base_url is not None and not self._base_url.path.endswith("/"):
    raise ValueError("base_url must have a trailing '/'")
```

`yarl.URL.join` is RFC 3986 reference resolution, so **a leading `/` resets to the host root**,
the opposite of httpx's append. Measured:

| base_url | request path | final URL |
|---|---|---|
| `https://h.example/api/` | `users` | `https://h.example/api/users` |
| `https://h.example/api/` | `/users` | `https://h.example/users` (leading `/` resets) |
| `https://h.example` | `users` or `/users` | `https://h.example/users` |
| `https://h.example/` | `users` | `https://h.example/users` |
| `https://h.example/api/` | `` (empty) | `https://h.example/api/` |
| `https://h.example/api/` | `./x` | `https://h.example/api/x` |
| `https://h.example/api/` | `../x` | `https://h.example/x` |
| `https://h.example/api/` | `x?q=1` | `https://h.example/api/x?q=1` |
| `https://h.example/api/?x=1` | `users` | `https://h.example/api/users` (base query dropped) |
| `https://h.example/api/` | `https://other.example/x` | `https://other.example/x` (absolute wins) |
| `https://h.example/api/` | `//other.example/x` | **not joined**: it has a host, so `url.absolute` is true; `_build_url` returns it unchanged and the request then fails with a bare `AssertionError` raised from `aiohttp/connector.py` (the probe asserts the raising file; there is no message) |

Construction rejections: `ClientSession(base_url="https://h.example/api")` and
`".../api?x=1"` raise `ValueError("base_url must have a trailing '/'")` (a path not ending in
`/`; `https://h.example` has the path `/` and is fine); `"/relative/"` and `"h.example/"` raise
`ValueError("URL should be absolute")` (from yarl). A `base_url` that works therefore always
has a path ending in `/`.

With `base_url` set, `s.get("/wire?q=1")` against `BASE` reaches the wire as `GET /wire?q=1`;
`ClientSession(BASE + "/svc/")`: `post("items")` is `POST /svc/items`, `post("/items")` is
`POST /items`.

**Without `base_url`**, a relative URL (`"/relative"`, `"relative"`, `"host/x"`) raises
`aiohttp.InvalidURL` (concretely `InvalidUrlClientError`, raised in `_request` from
`_build_url`'s failure) before any request is sent; so does `aiohttp.request("GET", "/relative")`.
`aiohttp.request` has no `base_url` parameter.

## urllib3 bodies

`urllib3._request_methods.RequestMethods.request` (quoted, abridged):

```python
method = method.upper()
if json is not None and body is not None:
    raise TypeError(
        "request got values for both 'body' and 'json' parameters which are mutually exclusive"
    )
if json is not None:
    ...
    if not ("content-type" in map(str.lower, headers.keys())):
        headers = HTTPHeaderDict(headers)
        headers["Content-Type"] = "application/json"
    body = _json.dumps(json, separators=(",", ":"), ensure_ascii=False).encode("utf-8")
if body is not None:
    urlopen_kw["body"] = body
if method in self._encode_url_methods:
    return self.request_encode_url(method, url, fields=fields, headers=headers, **urlopen_kw)
else:
    return self.request_encode_body(method, url, fields=fields, headers=headers, **urlopen_kw)
```

and `RequestMethods.request_encode_body`:

```python
if fields:
    if "body" in urlopen_kw:
        raise TypeError("request got values for both 'fields' and 'body', can only specify one.")
    if encode_multipart:
        body, content_type = encode_multipart_formdata(fields, boundary=multipart_boundary)
    ...
    extra_kw["body"] = body
    extra_kw["headers"].setdefault("Content-Type", content_type)
```

Measured:

- Wire, POST: `json={"k":1}` sends `{"k":1}` (compact) as `application/json`; `body=b"raw"` and
  `body="text"` send exactly those bytes with **no Content-Type**; `fields={"k":"v"}` sends
  `multipart/form-data` (never form-urlencoded: `encode_multipart` is true by default); none sends
  no body.
- `fields=` goes to the **URL query** (`?a=1&b=2`) when the method is in
  `RequestMethods._encode_url_methods` = `{"DELETE", "GET", "HEAD", "OPTIONS"}`, and to a
  multipart **body** for every other method (POST, PUT, PATCH, anything else).
- `json=` and `body=` are sent on every method, GET and DELETE included.
- **Rejected combinations (`TypeError`, nothing sent):** `body` + `json` on every method;
  `fields` + `body` and `fields` + `json` on POST/PUT/PATCH (where `fields` would become the
  body); all three together (the `body`/`json` error is raised first).
- **Accepted:** `fields` + `body` and `fields` + `json` on GET/HEAD/DELETE/OPTIONS (`fields`
  goes to the URL, the body is sent as given). There is no precedence among the keywords: they
  are mutually exclusive where they would compete for the body.
- Falsy values: `body=None`, `json=None` and an empty `fields={}` count as absent
  (`body=b"x", fields={}` sends `x`; `json=..., fields={}` sends the JSON). `json={}` is not
  `None`, so `json={}` with `body=b"x"` still raises.
- Headers: `json=` sets `Content-Type: application/json` unless the caller's `headers` already
  has a `content-type` (any case), in which case the caller's value is kept. `fields=` multipart
  also keeps a caller's `Content-Type` (`setdefault`). `body=` never sets one.

## urllib3 module level

`urllib3.request(method, url, *, ...)` forwards every argument to
`_DEFAULT_POOL.request(method, url, body=..., fields=..., headers=..., ..., json=...)`, where
`_DEFAULT_POOL` is a `urllib3.PoolManager`. So it follows exactly the rules above (measured: json
body, `fields` to the URL on GET, `body` + `json` raises `TypeError`).

urllib3 has **no base URL**. A relative URL (`"/relative"`) raises
`urllib3.exceptions.LocationValueError` ("No host specified.") on both the module and a
`PoolManager`; every URL is absolute.
