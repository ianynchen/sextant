# CP-52 — Quarkus gRPC's `@GrpcService` and `@GrpcClient`, and how a client is named when its value is left out

**Version scope.** Everything below is measured against `quarkus-grpc-api`, `quarkus-grpc` and
`quarkus-grpc-deployment` **as their own manifests state them** (`Implementation-Version` —
`3.17.5`, the fixture's Quarkus, when this record was made), read by `probe.py` out of the
local Maven repository — never the directory name this harness found them under, which is the
CP-5 failure the convention exists to prevent. These are platform behaviour of Quarkus
`3.17.5` and a later release is free to change any of them, so the verdicts here bound to the
version in the table and to nothing wider.

**Why it was measured.** Ruling 3 of the Quarkus messaging design (spec 2026-10-24, §1, §3d)
adds `io.quarkus.grpc.GrpcService` to `grpc-spring.yml`'s corroboration list and gives
`io.quarkus.grpc.GrpcClient` its own `injected_client` catalog, because its naming rule differs
from net.devh's: a client whose value is left out is named by the field. Both annotations'
identities, where each may sit, `GrpcClient.value()`'s default, and where the extension turns
that default into a name are read off the jars before the catalogs state them.

## What the rows say

**Rows 1–3 — two qualifiers, in `quarkus-grpc-api`.** `@GrpcService` sits on a TYPE, FIELD or
PARAMETER and has no members; `@GrpcClient` sits on a FIELD or PARAMETER. Neither class is in
the `quarkus-grpc` jar a module declares; `quarkus-grpc`'s pom declares `quarkus-grpc-api`,
which carries both — the same provenance note W53 records for Spring gRPC's starter.

**Rows 2 and 5 — the value's default is a sentinel, and the sentinel means "the element's
name".** `GrpcClient.value()` defaults to `"<<element name>>"` (also the constant
`ELEMENT_NAME`). `discoverInjectedClients` compares the value with that sentinel, and a value
equal to it — or absent — names the client by the injection point: a field's name, or a
parameter's name. So `@GrpcClient HelloGrpc hello` is the client `hello`, configured under
`quarkus.grpc.clients.hello.*` (§2's quickstart).

**Row 6 — an EMPTY value is not the default; it fails the build.** An explicit value is
`trim()`med and, when empty, raises "client name cannot be empty". So `@GrpcClient("")` is a
deployment error, not a field-named client: the field-name rule applies to an OMITTED value
only. A parameter whose name the class file does not record (no `-parameters`, no `-g`) also
fails the build.

**Row 7 — in Quarkus, `@GrpcService` is required.** Every class bean that is a
`BindableService` or a `MutinyService` — other than a generated `MutinyBean` — must carry
`@GrpcService` (and be `@Singleton`), or the build fails. This differs from Spring gRPC,
where the annotation is optional (`grpc-spring.yml`'s own comment): a Quarkus service class
without it does not deploy.

## What this does NOT measure

* **A client's address.** `quarkus.grpc.clients.<name>.host` / `.port` (and their defaults)
  are the client configuration ruling 3C logs as its own item; this probe reads only how the
  `<name>` is chosen.
* **The service's wire identity.** `@GrpcService` names no service; the wire name comes from
  the generated `*Grpc` class's `SERVICE_NAME`, which `grpc-java.yml` reads (CP-8). The
  Mutiny-generated stubs Quarkus adds (`MutinyGrpc`, `MutinyStub`) are not read here.
* **Versions other than `3.17.5`.** The field corpus's Quarkus is `3.40.1.1`; its gRPC jars
  were not fetched, so the rows bound to `3.17.5`.
