# How FastAPI reads a model marked `Query()`, `Header()` or `Cookie()` (plan 2, Task 9, R25)

Backs ruling R25 (query models) in `catalogs/fastapi.yml` and `request_requirements.
model_parameter_row`. `fastapi_param_models.py` produced every result below.

**Version scope.** FastAPI **0.162.0** and **0.115.12**, each with pydantic **2.14.3**, each as the
running process reported it (`fastapi.__version__`, `pydantic.VERSION`), each run in its own
throwaway environment (the ones `fastapi_rules.md` names). Every verdict below holds for those two
and for no other version.

Generated by `scripts/probes/fastapi_param_models.py`, one run per environment. Each column header

## The rule (0.162.0)

`dependencies/utils.py` `_get_param_aliases` (R 1432-1468): a model field's request key is
`get_validation_alias(field)`, which is `validation_alias` else the field's `alias` (pydantic's:
the written `alias`, else the generator's name, else the name); a `Header` model converts `_` to
`-` only where that key IS the field's name (`if convert_underscores and alias == field.name`);
`AliasChoices` adds each choice; `populate_by_name`/`validate_by_name` adds the field's own name.
`serialization_alias` plays no part. A field is required where pydantic requires it (no default).
A name starting with `_` is no field (pydantic's private attribute), so no parameter.

So a model's parameters are one per field, named by the field's input name (the shape model's
`input_name_from`, else its generator, else the name, the `Header` spelling applied to the name
alone), required where the field writes no default. A field read under more than one key
(`AliasChoices`, `populate_by_name` on a renamed field) is published under the first at `partial`;
one whose input name is not a literal (`AliasChoices`) names nothing, `unresolved`.

**0.115.12 differs**, and the catalog mirrors 0.162.0: its OpenAPI names a `validation_alias`
field by its own name, and it reads no field whose input name is an `alias` or a generated name
(the documented parameter is never read). Code relying on 0.115.12's behaviour reads nothing.
