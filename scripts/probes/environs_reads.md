# Reads through `environs` (ruled 2026-11-26)

Measured by `environs_reads.py`, run as
`fixtures/orders-django/.venv/bin/python -I scripts/probes/environs_reads.py`.
Every line below is an `assert` in the script.

**Version scope.** environs 14.5.0 on CPython 3.13.14, the interpreter of the orders-django
fixture's environment. Every verdict holds for that version of the library and no other.

## Observations

Generated by `scripts/probes/environs_reads.py`, run in `fixtures/orders-django`'s own
environment. The column is the `environs` version the running process reported
(`importlib.metadata.version('environs')`, the second line it prints), not the version the
lock asked for. Every row is an `assert`.

| Rule | 14.5.0 |
|---|---|
| the classes | `environs.Env`; `environs.FileAwareEnv` is a subclass of it |
| the read methods | `__call__`, `str`, `bool`, `int`, `float`, `list`, `json`: class attributes of `Env` a factory made (`_field2method`), not a `def` |
| parameters | `(name, default)`, by position or keyword, on both classes |
| unset key | with a default, the default; with none, `environs.EnvError` |
| set key | its value, parsed, whatever default the call carries |
| `FileAwareEnv` | where `KEY_FILE` is set it names a file whose content is the value, read before `KEY`; `Env` reads `KEY` alone |
| `Env.prefixed(p)` | inside the block the key read is `p + name` |

## What the catalog states

Each of the seven methods on each class is an `environment_reads` entry: the value is the
expression `${KEY}`, with a literal default as `${KEY:-default}`
(`value-models/python-environment.yml`). Two limits, both recorded there:

- `FileAwareEnv` has a second source, the file `KEY_FILE` names. The entry states the key
  alone (ruled 2026-11-26, option A): the deployment sets the value under the name `KEY`,
  directly or through the file. A value with two sources is OI-578.
- A read inside `env.prefixed(p)` is published as `${name}`, not `${p + name}`. No use in the
  four Django projects measured.
