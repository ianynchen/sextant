Backs `ingress/extract/python/pytest_collection.py`: the Python scanner does not read test code
(the user's ruling of 2026-11-09, "We only care about code that eventually goes to prod").
`scripts/probes/pytest_collection.py` produced every result below.

**Version scope.** pytest **9.2.0** on Python **3.14.10**, as the running process reported them
(`pytest.__version__`), run with polar's environment (`examples/py-polar/server/.venv`). Every
verdict below holds for that version and for no other. The search order and the file loaders
were also read in that version's `_pytest/config/findpaths.py` (`CONFIG_LOADERS_BY_NAME`,
`locate_config`), the `testpaths` glob in `_pytest/config/__init__.py` (`_decide_args`), and the
name match in `_pytest/python.py` (`pytest_collect_file`) and `_pytest/pathlib.py`
(`fnmatch_ex`).

## What Sextant takes from this

- **The settings file.** In each folder from the scanned root upward, pytest looks for
  `pytest.toml`, `.pytest.toml`, `pytest.ini`, `.pytest.ini`, `pyproject.toml`, `tox.ini`,
  `setup.cfg`, in that order. The first one that holds pytest settings is chosen. A
  `pytest.ini` is chosen even with no `[pytest]` section; a `pyproject.toml` with no pytest
  table is passed over and the search goes on up. pytest goes up to the file system's root;
  Sextant stops at the analysed root, where `.sextantignore` is also read.
- **`testpaths`** are globs, read from the settings file's folder (pytest globs them from the
  folder it runs in, which is that folder when it runs with no arguments). Each value of the
  `args` kind is a list as written, or a string split as a shell splits it.
- **`python_files`** replaces the default `test_*.py` and `*_test.py`. A pattern with no `/` is
  matched against the file's name, one with a `/` against the whole path, preceded by `*/`.
- **The user's ruling adds to what pytest collects.** Every file below a `testpaths` entry or
  a folder named `tests` or `test`, and every `conftest.py`, is test code, so a helper module
  beside the tests is not scanned either. Where `testpaths` is set, the name patterns still
  apply outside it (`app/test_inline.py` above is test code by its name).
